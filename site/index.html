How it works

Four numbers,
one feedback loop.

I.

Real keystrokes

Playwright opens a fresh Chromium, reads the active word and its index from the page in a single call, and sends trusted key events. Reading them separately raced the page and retyped words.

II.

WPM on target

Keystrokes run on a clock, and a feedback loop compares counted characters to where they should be, so typo overhead and browser latency don't drag the score down.

III.

Consistency

Monkeytype's consistency formula is inverted to find the speed variation it implies. A per-second speed profile with warm-up and fatigue is scaled to exactly that, minus the jitter per-key timing already adds.

IV.

Accuracy & raw

An error budget decides when to hit a neighbouring key, pause, and backspace it. Raw above WPM comes from occasionally leaving a word wrong, which counts for raw but not WPM.

Measured

Target vs. actual.

Real runs against monkeytype.com in guest mode. The number after the slash is what was asked for.

Short tests swing more: a 50-word run overshot by 7%. 30s+ tests usually land within about 5%.
Run it yourself

Local by design.

The bot needs a real browser on your machine, so it runs locally instead of on this site. Setup takes a minute.

  • 01Every run uses a fresh guest browser, so nothing is saved to an account or sent to a leaderboard.
  • 02The control panel keeps one Monkeytype window open between runs, and Stop only stops the typing.
  • 03Every result is appended to results.jsonl.
# get it
git clone https://github.com/beastb728/ghostkeys
cd ghostkeys
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/playwright install chromium

# control panel → http://127.0.0.1:8765
.venv/bin/python panel.py

# or the command line
.venv/bin/python ghostkeys.py --preset fast --mode "time 30"
